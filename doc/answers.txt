  • Apache CXF: `wsdl2java` CLI or `cxf-codegen-plugin` to generate service 
    interfaces and data types, then compile/package.
  • JAX-WS: `wsimport` CLI or `jaxws-maven-plugin` to generate client stubs and

Question 3: Explain me the content of the folder `/Users/albertohernandez/Documents/projects/loc3x1-camel-route/target/` 
and tell me if this was created bt my mate or was created as byproduct of my mate's code.

Answer:
The `target/` folder is Maven’s build output directory. It is created automatically when 
you build or run the project with Maven (e.g., `mvn compile`, `mvn package`, or `spring-boot:run`). 
Your mate did not handcraft its contents; instead, he authored the source code and build 
configuration, and Maven produced `target/` as a byproduct of compiling and preparing the 
application. Here’s what the items in your `target/` represent:
- `classes/`: The compiled application and copied resources that will be on the runtime 
  classpath.
  • `com/`: Compiled `.class` files for Java sources under `src/main/java` (controllers, 
    services, processors, utilities).
  • `application.yml`: Copied from `src/main/resources` — runtime configuration.
  • `camel/`, `hello-rest.yaml`, `loc3x1-rest-old.yaml`, `loc3x1-routes.yaml`, `routes.yaml`: 
    Camel YAML route definitions copied to the classpath so Camel can load them at runtime.
  • `templates/`: Freemarker templates copied to the classpath for any code-gen/utilities 
    or templated content.
  • `source.xml`: Any resource XML copied for use by the application or tests.
- `generated-sources/annotations/`: Sources generated by annotation processors (e.g., Lombok, MapStruct) 
  during compilation. Maven references these when compiling. This folder indicates annotation processors 
  ran successfully and produced helper classes or mappers.
- `generated-test-sources/test-annotations/`: Similar to the above but for test sources, if any 
  annotation processing applies to tests.
- `maven-status/maven-compiler-plugin/`: Metadata produced by Maven’s compiler plugin (e.g., 
  lists of compiled sources, status files). Useful for incremental compilation and IDE tooling.
- `test-classes/`: Compiled test classes from `src/test/java`, if present. Even if there are 
  few or no tests, Maven will create the directory during the build lifecycle.

What you don’t currently see (but may appear depending on the build goal):
- Packaged JAR: Running `mvn package` would typically create `target/<artifactId>-<version>.jar` 
  (for Spring Boot, usually an executable fat JAR). Since you’ve been using `spring-boot:run` 
  with `-DskipTests`, Maven starts the app directly and may not produce a packaged JAR in 
  `target/` unless you explicitly run `mvn package`.
Summary:
- The `target/` folder contents are a byproduct of the build and run process, driven 
  by your mate’s code and `pom.xml`. They are not manually created deliverables but the 
  compiled classes and runtime resources Maven assembles to run the application.
